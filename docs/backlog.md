# Backlog

The one list of open work, grouped in the order the work is expected to reach it and ranked within each group. Items come from the plans' follow-up sections (kept there as history), the audits and the reviews; the source is in brackets. Close an item by deleting it in the commit that fixes it.

## State Builder, detector and Verifier

1. **`meta.json` and qualifier contracts.** A `contracts/` model for `meta.json` (match, teams, roster; `period_lengths_s` with integer keys, scheduled or actual end stated) and typed qualifiers (a set-piece `kind` enum; sprint `speed_kmh` and `distance_m`), exported, before product code reads either. Have the Match Clock check the event count against it. [engine-core]
2. **Product code sees no seed and no future.** `write_match` puts the `seed` in `meta.json`, which sorts all 56 suite matches into planted or decoy, and the **final score**, which a live score must never start from. Product ingestion gets a typed allowlist of match metadata; runtime game state comes only from events the clock has delivered. [final review, astra F05]
3. **The State Builder measures what the engine planted.** Pressure rate uses the same zone on both sides of the ratio (x < 63 in the opponent's frame, x > 42 in the presser's); sprints read `distance_m` and `speed_kmh`; possessions are segmented on team changes, set pieces included; period markers stay out of per-team counts. An empty window or zero denominator returns `insufficient_data`, never NaN or a plausible zero. A test in `tests/` checks that `state/` agrees with `engine/visibility.py` on a few suite matches. [engine-core, planted-signal, audit 10-23, astra F08]
4. **Record the whole tool call.** An immutable record of each call: canonical arguments, match-clock cutoff, implementation version, evidence set and baseline version, so the Verifier can recompute exactly. [astra]
5. **Support rules** (`docs/support-rules.md`). Per-metric minimum thresholds for hypotheses and counter-tests, after which `check_counter_test` also checks counters on other metrics. Sample-size minimums set knowing the demo's 58–63' window holds 17 Northvale passes and 18 in-zone actions (or the card uses the ground-truth 56–64' window). Channel-share bands set on the dev split, never to make the demo come out a particular way. [contract-hygiene, planted-signal]
6. **Detector.** Compare thresholds tuned on dev with the validation hit rates: the press story clears on pressure rate in 82% of matches, on long-ball share in 85%, on either in 100%; the flank story in 50%. Check the 74' honest-silence beat on seed 4434 (Harbour City score at 77:09). [planted-signal]
7. **A season baseline for physical claims.** Ordinary tiredness makes sprint falls common (Harbour City's 58–63' sprints fall by at least 15% in 70% of validation matches), so the Physical agent and its challengers need a same-window season baseline. `state/season_baselines.json` needs a seed range no evaluation split uses (spec §11.1). [contract-hygiene, audit 10-22]

## Agents and evaluation

1. **Chasing the result or a press change.** Synthesis makes chasing the result primary only if the team's own long-ball share rises; otherwise press intensity is primary and the score is a secondary cause. Once agents exist, a fixture test pins m01's 63' card: press intensity up primary, chasing the result secondary. The suites never plant a press rise by a trailing team, so tuning on dev would otherwise learn the opposite. [audit 10-23]
2. **The demo's fatigue rejection depends on the claim.** Controls are now scored on what they leave of the hypothesis's change. On m01, Northvale's sprints fall 30.5% and Harbour City's 21.2%, leaving 9.3 points: a claimed fall above 18.6% is refuted, one from 9.3% to 18.6% only weakened. Pin the Physical agent's real claim in the m01 fixture test, and say in the video only what that run shows. [astra F02]
3. **Evaluator matching.** Match the planted team as well as the class. Fixed metric names for headline and all-script recall, with a check that the headline count plus the exclusions equals the all-script count. [planted-suites, contract-hygiene]
4. **A comparison that proves it is paired.** `VariantComparison` refuses a run compared with itself, carries the `flag_set_id`, and is built by loading both runs and checking cohort, split, suite digest, flag set, model and budgets; the paired difference comes from recorded per-case results. An `Exclusion`'s observables must be its class's `CAUSE_OBSERVABLES`. Freeze the benchmark and configuration before the held-out run, run it once for reporting, and never tune prompts against held-out results. [planted-suites, astra F07, F09]
5. **Name the suite version a run scored**: a digest of the scripts and ground truth that an `EvalRun` cites, as it cites its flag set. [planted-suites]
6. **Cross-examination.** One counter-test per challenger per hypothesis, recorded by the orchestrator, which also fills a control's `hypothesis_change` from the hypothesis's own test. `HypothesisTest.outcome` computed from the prediction, not set freely. `check_counter_test` groups a team with its players ("NV-03") as well as its units. A counter on another metric is refused until a relation is defined, with fixtures for a contradiction and a non-contradiction. [contract-hygiene, astra F03]
7. **Recovery and corrections are idempotent.** Persist each stage's completion key and output; tell completed work from an interrupted write; use stable batch, revision and cue ids so a retry never publishes a card twice, charges an attention budget twice or applies an amendment twice. Test failure after a write but before its acknowledgement. [astra]
8. **Suite size.** About 28 held-out matches count toward recall, so a recall of 75% has a 95% CI of about ±16 points, and an A-vs-B difference will rarely exclude zero. Ten held-out decoys are also a small basis for a broad restraint claim. Size the held-out suite from the per-case cost after the first full run; plan the proof narration on the "reported as measured" variant. [audit 10-23]
9. **Team identity.** The display name is used as a team's identifier across contracts and engine, and unit and player membership is read from string prefixes. Give teams a stable id and resolve units and players through the roster before scoring or cross-examination. [audit 10-22, astra]

## Ledger and surfaces

1. **A real publication boundary.** A card's status set after construction, or an edit inside its verification, skips the rule-6 gate, and `validate_assignment` would not catch nested edits. Validate the serialised card at every ledger write and publication, move status through explicit transitions, and bind each verification to the exact revision it checked. [contract-hygiene, audit 10-23, astra F06]
2. **A document per card revision**, so a withdrawn card keeps its earlier passing verification (spec §10). [contract-hygiene]
3. **Fast-lane cards.** Check the lane and moment type before the outcome, so a goal is never "No clear cause"; refuse `investigating`, `cross_examined`, `verified` and `rejected` if the Director ever sets them. [contract-hygiene]
4. **Evidence that teaches the product.** The fan card: one plain explanation, two before/after values and a qualified alternative. The analyst view: the exact tool calls and the rejected hypotheses. A correction replaces the old card visibly and keeps it in the history. Shots all end at the goal centre in the engine, so draw outcome markers, never trajectories. [astra]

## Engine, realism and tooling

1. **Realism report.** Record or fix: every shot ends at (105, 34); dribbles go straight ahead; sprint starts use the ball at the minute tick; sprint events depend on the seed alone, not on play; about 27 goal kicks a match and no corners; about 28% of throw-ins start with a carry or dribble; about 22% of on-ball actions reflect off x = 97 and 38.5% start in the last 30 m; long-ball shares near 40% under a strong press. Fixing any of these changes the random draws: recalibrate and re-pick the demo seed by its rule. [engine-core, planted-signal, audit 10-23]
2. **First-half changes.** Planted changes before half-time are refused: spec §7.2's minutes-before baseline is not implemented. A first-half `at` after the played stoppage applies only at the second-half kick-off; refuse an `at` after 45+1:00 or document it. [planted-suites, engine-core]
3. **Per-observable seed counts** are not recorded in `ObservableCheck`; the flag set lists every seed run. [planted-suites]
4. **Growing the suites.** Each planted match tries seeds of its own within a 300-seed block, so at ten matches per class some score-triggered matches would find no usable seed. Widen the block (decoys and paired runs higher up the split's range) before resizing. [audit 10-23 #2]
5. **Schemas.** The schema check misses a stale file for a model removed from `SCHEMAS`; export `CrossExamination` in serialization mode when it is exported, or its computed `result` is missing. [contract-hygiene]
6. **Test time.** About 75 s, most of it engine statistics. Mark those tests slow and run `-m "not slow"` locally, everything in CI; `tests/test_engine_mechanisms.py` runs the same 40 m01 simulations for each of its three tests. [planted-signal, audit 10-23]
7. **Engine hardening.** Derive the parameter sets and `PARAM_RANGES` from one table; list the `EDGES` interventions out of time order in `tests/test_engine_params.py`; catch `UnicodeDecodeError` in the CLI's load step; rename `Streams`' `minute` argument to `bucket`; import the pitch constants from `contracts`; give `--seed` a metavar. [engine-core]
